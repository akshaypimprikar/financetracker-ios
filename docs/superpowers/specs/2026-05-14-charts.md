# Charts — Design Spec

**Date:** 2026-05-14
**Status:** Draft

## Overview

Adds two data visualisation charts to existing detail screens using Swift Charts. `AccountDetailView` gets a running balance line chart showing how an account's balance has evolved over time. `BudgetDetailView` gets a month-over-month bar chart showing total spending for that budget's category across the last 6 months. Both charts are embedded in new `Section`s within the existing `List` — no new screens. All chart tokens are already defined in `Theme.Charts`.

---

## Decisions & Constraints

| Decision | Choice | Rationale |
|---|---|---|
| Chart library | Swift Charts (system) | Native, no dependency, ships with iOS 26 |
| Where to embed | New `Section` inside existing `List` | Keeps screens cohesive; no new navigation |
| Bar chart granularity | Month-over-month, last 6 months | Most actionable — shows trend, not noise |
| `Decimal` → `Double` conversion | ViewModel layer | Services stay pure; Views receive chart-ready types |
| Chart hidden when empty | Yes — section omitted when data is empty | Avoids empty axes confusing the user |
| Initial balance point | Emitted at first transaction's date | Anchors the line chart baseline without fabricating dates |

---

## Architecture

No new layers. Changes touch:

```
BalanceService          ← new runningBalance(for:transactions:) method + BalanceDataPoint type
BudgetCalculationService ← new totalSpent(transactions:) method + MonthlySpendingPoint type
AccountViewModel        ← new runningBalanceData(for:) computed method
BudgetViewModel         ← new monthlySpendingHistory(for:) method
AccountDetailView       ← new "Balance History" Section
BudgetDetailView        ← new "Spending History" Section
```

Data flow for the line chart:
```
AccountDetailView
  → AccountViewModel.runningBalanceData(for: account) → [(Date, Double)]
    → transactionRepo.fetch(for: account)
    → balanceService.runningBalance(for:transactions:) → [BalanceDataPoint]
    → map Decimal → Double
```

Data flow for the bar chart:
```
BudgetDetailView
  → BudgetViewModel.monthlySpendingHistory(for: budget.category) → [(Date, Double)]
    → transactionRepo.fetch(for: category, in: month) × 6
    → budgetCalcService.totalSpent(transactions:) × 6
    → map Decimal → Double
```

## Data Models

No new `@Model` classes. Two new value types (not persisted):

```swift
// FinanceTracker/Services/BalanceService.swift
struct BalanceDataPoint: Identifiable {
    let id: UUID
    let date: Date
    let balance: Decimal

    init(date: Date, balance: Decimal) {
        self.id = UUID()
        self.date = date
        self.balance = balance
    }
}

// FinanceTracker/Services/BudgetCalculationService.swift
struct MonthlySpendingPoint: Identifiable {
    let id: UUID
    let month: Date      // normalised to first day of month
    let spent: Decimal

    init(month: Date, spent: Decimal) {
        self.id = UUID()
        self.month = month
        self.spent = spent
    }
}
```

## Domain Services

### `BalanceService` — new method

```swift
func runningBalance(for account: Account, transactions: [Transaction]) -> [BalanceDataPoint]
```

**Contract:**
- Input transactions need not be sorted — the function sorts by date ascending internally.
- Returns `[]` when `transactions` is empty.
- First point: `(date: transactions.first.date, balance: account.openingBalance)` — anchors the chart at the opening balance before the first transaction is applied.
- Subsequent points: one per transaction, each with the cumulative balance after applying that transaction. Balance logic reuses the same credit/debit/transfer rules as the existing `balance(for:transactions:)` method.
- All balance values are `Decimal`.

### `BudgetCalculationService` — new method

```swift
func totalSpent(transactions: [Transaction]) -> Decimal
```

**Contract:**
- Returns the sum of `.amount` for all `.debit` transactions. Credit and transfer transactions are ignored.
- Returns `Decimal.zero` for an empty input.
- Pure function, no side effects.

## Navigation

No new screens or sheets. Changes are additive sections inside existing views:

- `AccountDetailView`: new `Section("Balance History")` inserted **before** the Transactions section. Hidden when the account has no transactions.
- `BudgetDetailView`: new `Section("Spending History")` inserted **after** the Progress section. Hidden when all 6 months have zero spending.

## Design

### Balance Line Chart (`AccountDetailView`)

Tokens used:

| Element | Token |
|---|---|
| Line stroke | `Theme.Charts.balanceLine` |
| Area fill | `Theme.Charts.balanceAreaFill` |
| Stroke width | `Theme.Charts.lineStrokeWidth` |
| Chart min height | `Theme.Charts.minHeight` |
| Horizontal padding | `Theme.Spacing.cardPadding` |
| Axis labels | `.caption` (Swift Charts default) |

Pattern from `docs/design-system.md`:

```swift
Chart(viewModel.runningBalanceData(for: account), id: \.date) { point in
    LineMark(x: .value("Date", point.date), y: .value("Balance", point.balance))
        .foregroundStyle(Theme.Charts.balanceLine)
        .lineStyle(StrokeStyle(lineWidth: Theme.Charts.lineStrokeWidth))
    AreaMark(x: .value("Date", point.date), y: .value("Balance", point.balance))
        .foregroundStyle(Theme.Charts.balanceAreaFill)
}
.frame(minHeight: Theme.Charts.minHeight)
.padding(.horizontal, Theme.Spacing.cardPadding)
```

### Spending Bar Chart (`BudgetDetailView`)

Tokens used:

| Element | Token |
|---|---|
| Bar fill | `Theme.Charts.spendingBar` |
| Chart min height | `Theme.Charts.minHeight` |
| Horizontal padding | `Theme.Spacing.cardPadding` |
| Axis labels | `.caption` (Swift Charts default) |

Pattern from `docs/design-system.md`:

```swift
Chart(viewModel.monthlySpendingHistory(for: budget.category), id: \.month) { point in
    BarMark(x: .value("Month", point.month, unit: .month),
            y: .value("Spent", point.spent))
        .foregroundStyle(Theme.Charts.spendingBar)
}
.frame(minHeight: Theme.Charts.minHeight)
.padding(.horizontal, Theme.Spacing.cardPadding)
```

All tokens are defined — no new `/design` run required.

## Future Extension Points

- **Chart annotations / callouts**: tapping a data point to show an exact value. Not in scope; Swift Charts supports `.chartOverlay` for this when needed.
- **Date range picker**: letting the user adjust the balance chart window (e.g. last 30/90/365 days). Plugs in as a toolbar control on `AccountDetailView`, feeding a `dateRange` parameter to `runningBalanceData`.
- **Spending bar chart beyond 6 months**: `monthlySpendingHistory` already accepts a count; surfacing a control to extend it is deferred.
- **Multiple-account aggregate chart**: a future Dashboard chart could reuse `runningBalance` across all accounts.
